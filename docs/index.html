●  Awake — always
      
Keeps your computer awake for exactly as long as the terminal is open.

      

        Every lock it takes is bound to the process itself. Close the terminal — or
        kill -9 it, however rudely — and normal sleep is back instantly.
        There is no daemon, no config to undo, and nothing left behind to clean up.
      

      

        $cargo install sleepless
      

    

  


  
  

    The problem
    
Every keep‑awake tool has an off switch you can forget.

    

      

        You start a long build, or a download, or a presentation, and you need the machine to
        stay up. So you reach for something that disables sleep. Then the build finishes and
        you close the lid, and three hours later the laptop is hot, flat, and still awake.
      

      

        That happens because most of these tools change a setting. A GUI toggle writes
        to a power profile. A helper script disables a timer. A background daemon holds a lock
        on your behalf and outlives the thing you actually cared about. All of it survives the
        program that set it — and all of it survives that program crashing.
      

      

        sleepless has no off switch to forget, because the process is the
        switch. While it runs, you are awake. The moment it stops, for any reason,
        you are not.
      

    

  


  
  

    How it works
    
The kernel is what releases the lock, not the program.

    

      On Linux, sleepless holds two independent locks, and neither one requires it to shut down
      politely. Try killing it — the hard way, with no chance to run cleanup code —
      and watch what each side does.

        Session bus
        
org.freedesktop.ScreenSaver

        

          Returns a cookie that is scoped to the D‑Bus connection. When the process
          dies the connection drops, the bus broadcasts it, and the compositor releases the
          inhibit on its own. Understood by GNOME, KDE, niri and most others.
        

      

      

        System bus
        
logind sleep:idle

        

          logind hands back an open pipe file descriptor and holds the lock for exactly as long
          as that fd stays open. Closing it is not something sleepless has to remember to do —
          the kernel closes every fd a process owns when it dies, SIGKILL included.
        

      

    


    

      That is the whole design, and it is why there is no --stop flag, no PID file
      and no state directory to get out of sync. Verify it yourself while it runs:
      systemd-inhibit --list | grep sleepless.
    

  


  
  

    What you get
    
A full‑screen status display, not a menu‑bar checkbox.

    


      

        At a glance
        
State is the colour

        

          Green and gently pulsing means the locks are held. Grey with a yellow banner means it
          paused on purpose. Red means it wanted the locks and could not get them — which
          you find out immediately, rather than when your machine sleeps mid‑build.
        

      


      

        Battery aware
        
Only while plugged in

        

          --plugged-only releases every lock the moment you unplug and takes them
          back when AC returns, checked every two seconds. Toggle it live with m
          without restarting.
        

      


      

        Linux
        
A tray eye

        

          A StatusNotifierItem that shows an open green eye while awake and a closed amber one
          while paused. Left‑click toggles the mode. If your bar restarts, it re‑registers
          itself; if you have no tray at all, it just says so and carries on.
        

      


      

        Yours
        
Custom splash screens

        

          Three are built in. Add your own in config.toml as block‑font text,
          inline ASCII art, or a path to an art file, each with its own colours, and cycle them
          with the arrow keys.
        

      


      

        Opt in
        
Lid‑close blocking

        

          logind treats the lid as a separate channel that ignores ordinary sleep inhibitors, so
          blocking it is deliberate rather than a surprise. If polkit refuses, sleepless keeps the
          other locks and marks lid as refused instead of failing.
        

      


      

        Scriptable
        
Headless mode

        

          --smoke N takes the locks, prints plain‑ASCII status, holds for N
          seconds and exits — no TTY required. It is how the test suite checks that the
          locks are real on every platform.
        

      


    

  


  
  

    Platform support
    
Linux is the developed path. The rest is honest about itself.

    

      The core guarantee holds everywhere: on all three platforms the underlying API is
      process‑scoped, so nothing outlives the program. What differs is how much is
      exposed and how hard it has been exercised.

      Two limits worth knowing before you rely on them. On Modern Standby laptops, Windows
      terminates power requests some minutes after the sleep timeout when running on battery,
      so --plugged-only is the dependable mode there. And on sway or Hyprland the
      suspend block still works, but screen blanking does not: the Wayland idle‑inhibit
      protocol needs a surface to attach to, and a terminal program has none.
    

  


  
  

    Get it
    
One binary, no runtime, nothing to configure.


    

      

        From crates.io
        
$cargo install sleepless

        

          Installs a single binary called sleepless. No runtime, no daemon,
          nothing else to set up.
        

      

      

        From source
        
$cargo install --path .

        

          Requires Rust 1.89 or newer. The dependency tree is pure Rust — no C toolchain,
          no pkg-config, no system libraries.
        

      

    


    

      Then
      
sleepless                    # stay awake while this runs
sleepless --plugged-only     # ...but not on battery
sleepless --inhibit-lid      # also block lid-close suspend (Linux)
sleepless --why "rendering"  # reason shown in systemd-inhibit --list

      

        Keys: m mode · l lid block ·
        ← → splash · q quit.
        Or just close the terminal.
